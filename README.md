# Дашборд пользователей

Фронтенд-приложение — дашборд со списком пользователей, получаемых из публичного API [dummyjson.com/users](https://dummyjson.com/users).

## Запуск

```bash
npm install
npm run dev
```

Приложение разворачивается на порту **5175** (указано в `vite.config.ts`).

## Архитектура и решения

### 1. За основу взят существующий стек
Я взял проект из `/Users/ivantereshchencko/Desktop/almaty camping/frontend` и унаследовал его конфигурацию:
- **Vite** — быстрый dev-сервер и сборка.
- **React 18 + TypeScript** — типобезопасность и современный UI.
- **Tailwind CSS** — утилитарные стили, адаптивность, тёмная тема (через CSS-переменные).
- **TanStack Query (React Query)** — кеширование, статусы загрузки и ошибок при работе с API.
- **Axios** — HTTP-клиент (уже был в исходном проекте).
- **Lucide React** — иконки.

### 2. Упрощение зависимостей
Из исходного проекта убраны специфичные для e-commerce библиотеки (`zustand`, `react-hook-form`, `recharts`, `zod`, Radix UI и др.), которые не нужны для readonly-дашборда. Это уменьшает размер `node_modules` и время установки.

### 3. Структура проекта (FSD-стиль)
Сохранена модульная структура, близкая к Feature-Sliced Design:
- `src/app/` — точка входа, провайдеры, стили.
- `src/pages/dashboard/` — страница дашборда.
- `src/widgets/` — крупные независимые блоки: список пользователей и модальное окно деталей.
- `src/entities/user/` — типы и API-запросы сущности "пользователь".
- `src/shared/` — переиспользуемые утилиты (`cn`, `query-client`, конфиг роутов).

### 4. Работа с API
Используется TanStack Query с `staleTime: 5 мин` и `refetchOnWindowFocus: false`, чтобы не нагружать сервер лишними запросами при переключении вкладок.

### 5. UI/UX
- **Статистика сверху** — быстрая сводка по ролям (всего / админы / модераторы / пользователи).
- **Поиск** — фильтрация по имени, email и username в реальном времени (локально, на клиенте).
- **Фильтр по ролям** — переключатели для быстрого отбора.
- **Таблица** — адаптивная, с аватарками, бейджами ролей и кнопкой просмотра деталей.
- **Модальное окно** — полная информация о пользователе без перехода на другую страницу.
- **Обработка состояний** — явные состояния загрузки и ошибок.

### 6. Почему порт 5175
Vite по умолчанию использует 5173. В задании был указан порт 5175, поэтому в `vite.config.ts` добавлена опция `server: { port: 5175, strictPort: true }`.
